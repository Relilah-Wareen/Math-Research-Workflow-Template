# 新路线探索提示词（不计研究轮次）

你现在只执行一次“新路线探索”，目标是为用户锁定的数学问题提出一个真正不同、
可证伪的下一轮研究规格。本次不证明最终引理，不增加研究计数。

## 最小必读上下文

开始时只完整阅读：

1. `AGENTS.md`
2. `notes/problem_statement.md`
3. `notes/research_handoff.md`
4. `iteration_state.json`

禁止一开始通读 `work_log.md`、全部前沿、全部证明、全部审计或全部文献卡。这样做是为了减少
历史路线的锚定，而不是允许忽略既有反例。

## 探索任务

1. 从 `notes/research_handoff.md` 的开放入口出发，提出 3--5 个结构上不同的候选路线。
2. 候选可适度借鉴其他数学方向，但必须落成本问题中的精确对象、输入、输出、方程约束与观测。
3. 对每个候选写出：
   - 核心机制；
   - 为什么可能比最终目标更容易；
   - 第一条单轮可证伪引理；
   - 最大失败风险；
   - 与哪条暂停路线最接近，以及实质新增了什么。
4. 先凭独立推理排序，选出唯一首选候选。
5. 只有选出首选后，才用 `rg` 在 `audit/`、`proof/`、`frontiers/`、`literature/` 和
   `work_log.md` 中搜索与该候选直接相关的关键词。只读取命中的必要文件，不通读全历史。
6. 根据定向核验决定：
   - 候选确有新机制：给出一个单轮可验收的 `current_gap`；或
   - 候选与旧失败同构：淘汰它，并对次优候选重复一次定向核验。
7. 最多定向核验两个候选。若都失败，明确停止，不得硬造第三条路线。

## 候选通过标准

新的 `current_gap` 必须：

- 保持锁定目标，不偷加特殊几何或增强数据；
- 只要求一个明确引理、反例或原始定理核验；
- 能在一次研究轮内得到“证明、严格反驳或精确条件错配”之一；
- 不把完整稳定性主定理、一般背景线性完备性或完整内部对应换名作为中间引理；
- 明确列出成功标准和失败标准。

## 落盘规则

- 每次探索必须创建新的审计文件，文件名须带有可辨识的路线名或时间标识，例如
  `audit/new_route_scout_<route>_<timestamp>.md`；不得覆盖、改写或复用任何已有 scout 文件；
- 若产生合格候选，只更新 `iteration_state.json.current_gap`、`last_iteration_summary` 和
  `stop_reason`，不得更新正向前沿或证明依赖图；
- 若无候选，保持人工停止状态并说明原因；
- `completed_iterations`、`total_iterations` 均不得增加；
- 不新增 F 编号，不修改锁定目标；
- 创建且只创建一个本地 commit，不得 push；完成后立即停止。

最终只汇报：候选列表、唯一首选、定向读取的文件、是否发现历史重复、精确新
`current_gap`、成功/失败标准、计数不变确认和 commit hash。

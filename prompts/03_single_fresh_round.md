# 单轮研究提示词（供脚本启动全新 Codex）

你正在执行本项目的一次、且仅一次独立研究轮次。

开始前只完整阅读 `AGENTS.md`、`notes/problem_statement.md`、`notes/research_handoff.md` 和
`iteration_state.json`。不得修改锁定目标，也不得一开始通读全部历史。

随后针对 `current_gap` 用 `rg` 搜索关键词，只读取与本轮候选直接相关的前沿、证明、审计、
定理卡和最近日志。正式确定结果前必须回到所有实际依赖的原文件完成验证；精简读取不允许
跳过证据核验。

## 当前路线门禁（动态读取）

本轮必须以 `iteration_state.json` 中的 `current_gap` 为唯一主问题，并结合时间上最新的路线
审计理解其准确范围。不得由旧批次提示词、旧工作日志或较早审计覆盖当前缺口。

开始研究前必须明确记录：

1. 当前 `current_gap` 的原文；
2. 最新路线审计建议继续、暂停或排除的路线；
3. 本轮问题为何严格属于当前缺口，而不是已经暂停、闭合或排除的旧路线。

若 `current_gap` 与旧文档中的“当前路线”“当前最小缺口”或建议发生冲突，以
`iteration_state.json` 和时间上最新的路线审计为准，并在本轮记录中指出冲突。不得擅自切回
标记为“暂停”的路线；若确有新证据足以重开，必须先完成一次不计数路线审计并停止，不能在
同一轮直接研究该旧路线。

不得从提示词中的举例反推研究方向。允许和暂停的路线只以当前 `current_gap`、精简交接及
定向核验到的最新审计为准；未来合法换线后，旧路线名称不应继续锚定新一轮。

特殊背景、有限维模型或显式例子只能用于严格验证或反驳当前候选，不能替代 `current_gap`
要求的一般对象，也不能作为无接边的正向子类成果计数。若无法提出满足当前缺口的精确候选，
应验证失败并停止，不得切换到旧路线凑足轮数。

本轮必须严格完成以下闭环：

1. 严格围绕 `iteration_state.json.current_gap` 只选一个明确且可在单轮验收的问题；
   选择前必须先对照精简交接，再定向搜索相关历史，禁止重复已经闭合、暂停或严格排除的路线；
   只有真正缩小当前缺口或严格排除当前候选的工作才可计数；
2. 开展一次实质性的定理核验、证明尝试、反例压力测试、桥接引理构造或路线排除；
3. 严格执行 `AGENTS.md` 的逐轮验证门；
4. 验证通过，才把成果写入前沿、依赖图、证明或文献记录，并将
   `completed_iterations` 和 `total_iterations` **各增加且只增加 1**；
5. 验证失败，则回滚暂定结论，记录失败原因，但两个计数均不得增加；
6. 所有证据和修改立即落盘；然后停止，不得自行开始第二轮。
7. 验证结论和全部文件落盘后，按照 `AGENTS.md` 的逐轮 Git 规则检查 staged diff，并创建
   且只创建一个本地 commit；验证失败也要提交失败记录，但不得增加轮数；不得 push。

禁止把一次回答拆成多个名义轮次，禁止预先撰写后续轮次，禁止一次增加两个或更多计数。
即使你认为下一步显然，也只能把它记录为建议，不能在本进程中继续执行。
若最终目标已被严格证明或否证，正确更新 `final_goal_status`；否则保持 `open`。

结束时只汇报：本轮选择的问题、实际工作、验证/回滚结果、修改文件、计数变化、commit hash、
当前最小缺口。
